# Прошивка INS10-A3: система орієнтації (AHRS) для Raspberry Pi Pico 1 / Pico 2

Прошивка читає ICM-42688-P, MMC5983MA та LPS22DF з плати INS10-A3 і видає орієнтацію у всіх 360° за трьома осями: кватерніон, крен, тангаж, рискання і компасний курс. В основі розширений фільтр Калмана з адаптивним відхиленням завад, відстеженням зсуву гіроскопа в реальному часі та температурною компенсацією. До неї додаються інструменти калібрування на ПК.

> **Стан перевірки.** Прошивка працює на справжніх платах INS10-A3 з Raspberry Pi Pico (RP2040) і Pico 2 (RP2350). На ній плату відкалібровано повністю: акселерометр і гіроскоп у підставці, магнітометр і температурний дрейф. Виміряні результати наведено в [технічному описі](../docs/uk/datasheet.md#точність-із-прошивкою-ins10_ahrs). Крім того, бібліотека фільтра та інструменти калібрування перевірені на ПК у симуляції (21 сценарій фільтра, 13 тестів інструмента), а логіка драйверів — на моделях трьох сенсорів рівня регістрів (5 тестів). Прошивка збирається без попереджень для Pico і Pico 2. Настільний додаток для неї — [INS10 Studio](../studio/README.md).

## Що вміє

| Вимога | Як реалізовано |
|---|---|
| Орієнтація у 360° з високою точністю | Мультиплікативний EKF на кватерніоні без особливих точок. Інтегрування гіроскопа третього порядку на кожній вибірці 512 Гц |
| Відхилення завад у складному середовищі | Адаптивна вага акселерометра (лінійні прискорення, вібрація) і магнітометра (магнітні завади). Магнітометр виправляє тільки курс і не може зіпсувати крен і тангаж |
| Зсув гіроскопа в реальному часі | Три стани фільтра, оновлення нульової швидкості у спокої, випередження за температурою |
| Калібрування магнітометра й акселерометра | `magcal`: hard/soft iron і вирівнювання осей до IMU. `imucal`: зсув, масштаб і перехресні зв'язки акселерометра, а заодно масштаб і неортогональність гіроскопа |
| Температурний дрейф | Виявлення перехідного процесу, самонавчання моделі «зсув гіроскопа від температури» з пам'яттю у flash, `thermalcal` для гіроскопа й акселерометра, періодичне SET/RESET магнітометра |

Докладно: [алгоритми](docs/ALGORITHMS.md), [калібрування](docs/CALIBRATION.md), [протокол і команди](docs/PROTOCOL.md).

## Очікувана точність

Числа із симуляції з шумами ICM-42688-P і MMC5983MA, [tests/test_main.c](tests/test_main.c). Перші рядки отримані з ідеально відкаліброваними сенсорами й показують межу самого фільтра. Два останні рядки містять залишкові похибки калібрування й чесніше описують реальну плату.

| Сценарій | Нахил, СКВ / макс | Курс, СКВ / макс |
|---|---|---|
| Спокій | 0,006° / 0,02° | 0,008° / 0,02° |
| Безперервне перекидання до 150 °/с | 0,03° / 0,06° | 0,08° / 0,22° |
| Ривки 0,3 g і тряска 0,5 g | 0,08° / 0,25° | 0,11° / 0,28° |
| Те саме, акселерометр без адаптації | 7,8° / 19,0° | 32° / 45° |
| Магнітні завади 25 мкТл по 15 с | 0,02° / 0,06° | 0,17° / 0,50° |
| Те саме, магнітометр без адаптації | 13,2° / 28,2° | 14,1° / 27,6° |
| Широкосмугова вібрація 0,2 g | 0,32° / 0,56° | 0,26° / 0,53° |
| Повільне плавне обертання 0,1–0,3 °/с | 0,01° / 0,02° | 0,07° / 0,23° |
| Усе разом із залишками калібрування, гіроскоп відкалібровано | 0,28° / 0,72° | 0,71° / 1,75° |
| Те саме, масштаб гіроскопа з заводським допуском 0,5 % | 0,71° / 2,90° | 1,40° / 3,98° |

Без магнітометра курс за 5 хвилин руху зі зупинками відходить до 1,9°. Під час прогріву на 20 °C з температурним дрейфом 0,3 °/с фільтр тримає зсув гіроскопа в межах 0,03 °/с. Після втрати 0,3 с даних під час перекидання курс повертається в межі 0,3° за три секунди. За годину роботи числових відхилень немає.

## Швидкий старт

1. Підключіть плату до Pico за [таблицею в посібнику](../docs/uk/user-guide.md#4-підключіть-модуль-до-pico). Достатньо восьми контактів J1; лінії переривань цій прошивці не потрібні.
2. Зберіть прошивку (див. [Збирання](#збирання)) і скопіюйте `build/pico/ins10_ahrs.uf2` або `build/pico2/ins10_ahrs.uf2` на Pico в режимі BOOTSEL.
3. Покладіть плату нерухомо на 2 секунди після ввімкнення. Світлодіод часто блимає під час початкового вирівнювання, потім коротко спалахує раз на секунду.
4. Відкрийте USB-порт у терміналі (115200, DTR увімкнено) і надішліть `help`. Або запустіть інструмент:

```sh
pip install -r tools/requirements.txt
python tools/ins10.py info
python tools/ins10.py monitor
```

5. Відкалібруйте плату: `imucal`, потім `magcal`, за бажання `thermalcal`. Порядок і поради в [docs/CALIBRATION.md](docs/CALIBRATION.md). Те саме, з покроковими майстрами й підставкою, робить [INS10 Studio](../studio/README.md). **До `magcal` магнітометр не використовується**, курс відлічується від напрямку на момент увімкнення й повільно дрейфує.

## Системи координат

Навігаційна система — схід, північ, верх (ENU). Зв'язана система збігається з осями мікросхеми ICM-42688-P: плата лежить компонентами догори, вісь Z дивиться вгору, акселерометр показує +1 g по Z, крен і тангаж нульові. Кватерніон `{w, x, y, z}` переводить вектор зі зв'язаної системи в навігаційну. Кути Ейлера рахуються в порядку рискання–тангаж–крен. Рискання додатне проти годинникової стрілки, якщо дивитися згори, і дорівнює нулю, коли вісь X дивиться на схід. Курс `heading` — звичний компасний: 0° на північ, зростає за годинниковою стрілкою. Північ магнітна, поки не задано схилення командою `cal set declination <градуси>`.

Осі на самій платі показано в [технічному описі](../docs/uk/datasheet.md#осі). Потік `$MAG` іде в осях MMC5983MA, а вони — дзеркальне відображення осей IMU: за даташитом MEMSIC вісь Z магнітометра дивиться в плату, тож у осях IMU `$MAG` дорівнює `diag(1, 1, −1)`. Прошивка цього не виправляє: `magcal` визначає взаємну орієнтацію з даних, разом із відбиттям, і записує її в матрицю калібрування магнітометра.

## Перевірка після підключення

Ці пункти перевіряють пайку, проводку й сенсори конкретної плати. Якщо якийсь не сходиться, причину шукайте з виводу `info` і `status`.

1. Прошийте `ins10_ahrs`. Команда `info` має показати `imu=ok clock=external odr_hz=512.000`, `mag=ok`, `baro=ok`. Значення `clock=internal` означає, що генератор 32,768 кГц не підхопився; фільтр працюватиме, але з виміряною частотою.
2. Плата нерухома, компонентами догори. У `status`: `accel` близько `0 0 1`, `norm` у межах 0,98–1,02 g (до калібрування). `gyro_bias` за модулем менше 1 °/с, прапорці `aligned still`.
3. У `status` рядок `imu:` має `gaps=0 overflows=0 bad=0 bus_errors=0`. Рядок `load:` показує частку процесора на фільтр. Якщо `largest batch` постійно більший за 10, цикл не встигає.
4. `mag:` — лічильник `samples` росте приблизно на 50 за секунду, `pairs` приблизно на 1 за секунду, `errors` не росте.
5. Поверніть плату на 90° навколо кожної осі й звірте кути в `monitor`. Після `magcal` кут нахилення поля `dip` у звіті має бути додатним у північній півкулі (у Європі близько +65° на широті 50° і +75° на 60°) і від'ємним із `--southern` у південній. Точне значення для вашого місця дає калькулятор [NOAA WMM](https://www.ngdc.noaa.gov/geomag/calculators/magcalc.shtml). Звіт також скаже, що осі магнітометра дзеркальні: на INS10-A3 так і має бути.
6. `cal save`, потім `reboot`, і `info` має показати `stored=1`.

## Збирання

Потрібен Pico SDK 2.2.0 або новіший. На Windows з розширенням Pico для VS Code:

```powershell
./build.ps1 -Board both
```

Скрипт збирає прошивку й копіює `ins10_ahrs.uf2` у `build/pico/` і `build/pico2/`. На інших системах:

```sh
cmake -S . -B build/pico2 -DPICO_BOARD=pico2 -DPICO_SDK_PATH=/path/to/pico-sdk
cmake --build build/pico2
```

Збирання перевірене з SDK 2.2.0 і GCC 14.2 для обох плат, а також із SDK 2.3.1 і GCC 15.2 для Pico 2. Розмір `ins10_ahrs`: близько 100 кБ flash і 11 кБ RAM.

## Тести на ПК

```powershell
./test.ps1
```

Скрипт збирає бібліотеку фільтра будь-яким компілятором C11 (на Windows CMake сам знаходить Visual Studio), запускає через CTest 21 сценарій фільтра і 5 тестів драйверів, а потім тести інструмента калібрування на Python. Вручну:

```sh
cmake -S tests -B build/host && cmake --build build/host --config Release
ctest --test-dir build/host -C Release --output-on-failure
python tools/tests/test_calib.py
```

Тести драйверів (`ins10_driver_tests`) компілюють [drivers/](drivers/) без змін проти моделей сенсорів у [tests/device_models.c](tests/device_models.c): FIFO ICM-42688-P з двома джерелами такту, перетворення MMC5983MA з полярністю SET/RESET, цикл готовності LPS22DF. Вони перевіряють послідовності налаштування, декодування, автомат магнітометра й поведінку при відмовах.

Разом із тестами збирається `ins10_replay`: він проганяє записаний лог сирих даних через той самий фільтр на ПК. Це зручно для налаштування параметрів на реальних записах без перепрошивання:

```sh
python tools/ins10.py log run.log --seconds 120
ins10_replay run.log > attitude.csv
```

## Обмеження

- Тривале прискорення в один бік довше 30 секунд (довгий розгін, тривалий віраж) фільтр зрештою сприйме за нахил. Без зовнішнього джерела швидкості, наприклад GNSS, цього не відрізнити; поріг задає `accel_diverge_s`.
- Магнітна завада, що триває довше хвилини й не змінюється, приймається за нове місцеве поле (`mag_ref_tau_s`). Курс тоді слідує за спотвореним полем.
- Повільне плавне обертання до 3 °/с навколо вертикалі **без каліброваного магнітометра** детектор спокою приймає за зсув гіроскопа: без компаса його нічим відрізнити. З каліброваним магнітометром і навколо горизонтальних осей це обмеження не діє.
- Після короткої зупинки вертикальна складова зсуву гіроскопа відома лише настільки, наскільки магнітометр підтвердив відсутність обертання (близько 0,1 °/с після 10 с спокою, 0,03 °/с після 30 с).
- Заявлені в `$ATT` сигми — це невизначеність самого фільтра. Залишкові похибки калібрування в них не входять.
- Вивід іде тільки через USB CDC. Барометр читається й видається, але у фільтрі орієнтації не використовується.

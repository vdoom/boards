# Jetson Orin Nano з JetPack 6.2: як увімкнути UART слота M.2 Key E

[M2-KeyE-UART](../../README.uk.md) · [English](../en/jetson-setup.md)

Ця інструкція вмикає UART слота M.2 Key E, щоб карта з'явилася як `/dev/ttyTHS3`. Вона написана для **плати розробника Jetson Orin Nano з JetPack 6.2** і підходить для будь-якої плати на несучій P3768 (Orin Nano, Orin NX) з JetPack 6.

Що відбувається: UART слота — це `uartb`, вузол дерева пристроїв `serial@3110000`. У стандартному дереві пристроїв NVIDIA його вимкнено. Невеликий оверлей дерева пристроїв вмикає його з драйвером швидкого UART і дає йому псевдонім `serial3`, звідки й назва `/dev/ttyTHS3`. Завантажувач застосовує оверлей під час кожного завантаження; нічого не прошивається.

Знадобиться: Jetson зі встановленим JetPack 6.2, що вже завантажується, клавіатура з монітором або SSH, і доступ до інтернету для одного пакета. Приблизно 10 хвилин.

## 1. Перевірте випуск

```bash
cat /etc/nv_tegra_release
```

Рядок має починатися з `# R36` — це JetPack 6. На R35 і старших (JetPack 5) цю інструкцію не перевіряли.

## 2. Вставте карту

1. Вимкніть Jetson і від'єднайте живлення.
2. Слот M.2 Key E розташований під модулем Jetson, і в ньому стоїть карта Wi-Fi/Bluetooth. Зніміть модуль так само, як для заміни карти Wi-Fi.
3. Відкрутіть гвинт карти Wi-Fi, від'єднайте від неї антени й вийміть її. Приберіть дроти антен так, щоб вони ні до чого не торкалися.
4. Вставте карту M2-KeyE-UART під кутом, притисніть і закріпіть тим самим гвинтом. Якщо на хвості є дроти, виводьте їх за край з боку гвинта. Для запасу можна наклеїти смужку ізоляційної стрічки між картою й модулем.
5. Поставте модуль на місце й увімкніть живлення. Червоний світлодіод PWR на карті засвітиться, щойно на слоті з'явиться 3,3 В.

UART ще не працює: його ввімкне оверлей.

## 3. Зберіть оверлей

```bash
sudo apt update
sudo apt install -y device-tree-compiler
wget https://raw.githubusercontent.com/vdoom/boards/main/m2-keye-uart/jetson/m2-keye-uartb-overlay.dts
dtc -@ -I dts -O dtb -o m2-keye-uartb.dtbo m2-keye-uartb-overlay.dts
sudo cp m2-keye-uartb.dtbo /boot/
```

Якщо на Jetson немає інтернету, перенесіть [`m2-keye-uartb-overlay.dts`](../../jetson/m2-keye-uartb-overlay.dts) на флешці або через `scp`. `dtc` має завершитися без помилок і створити `m2-keye-uartb.dtbo`.

## 4. Додайте оверлей у запис завантаження

Спершу збережіть копію налаштувань завантаження:

```bash
sudo cp /boot/extlinux/extlinux.conf /boot/extlinux/extlinux.conf.orig
sudo nano /boot/extlinux/extlinux.conf
```

Знайдіть рядок `DEFAULT primary` (назва після `DEFAULT` може бути іншою). Потім знайдіть секцію `LABEL` з цією назвою й додайте в її кінець один рядок з таким самим відступом, як в інших:

```
LABEL primary
      MENU LABEL primary kernel
      LINUX /boot/Image
      ...                                   (наявні рядки не змінюйте)
      OVERLAYS /boot/m2-keye-uartb.dtbo
```

Якщо в секції вже є рядок `OVERLAYS`, наприклад записаний jetson-io для 40-контактного роз'єму, другий не додавайте. Допишіть файл у наявний рядок через пробіл:

```
      OVERLAYS /boot/some-other-overlay.dtbo /boot/m2-keye-uartb.dtbo
```

Збережіть Ctrl+O, Enter і вийдіть Ctrl+X.

Запасний варіант, за бажанням: скопіюйте всю секцію `LABEL primary` під неї саму, перейменуйте копію на `LABEL backup` і `MENU LABEL backup kernel` та видаліть із копії рядок `OVERLAYS`. Якщо з оверлеєм Jetson колись не завантажиться, виберіть `backup` у меню завантаження під час старту.

## 5. Перезавантажте й перевірте

```bash
sudo reboot
```

Після перезавантаження:

```bash
tr -d '\0' < /proc/device-tree/bus@0/serial@3110000/status; echo   # okay
ls -l /dev/ttyTHS3
dmesg | grep -i 3110000
```

- `okay`: UART увімкнено. `ls` показує `/dev/ttyTHS3`, а `dmesg` — драйвер, під'єднаний до `3110000.serial`.
- `disabled`: оверлей не застосувався. Перевірте рядок `OVERLAYS`, назву файлу в `/boot` і те, що ви редагували секцію, названу в `DEFAULT`. Якщо все правильно, скористайтеся способом із кроку 8.

## 6. Доступ до порту без sudo

`ls -l /dev/ttyTHS3` показує групу, якій належить порт, зазвичай `dialout`. Один раз додайте себе до неї, потім вийдіть із системи й увійдіть знову:

```bash
sudo usermod -aG dialout $USER
```

## 7. Перевірка петлею

На площадках хвоста з'єднайте TX з RX, а також RTS із CTS, якщо ці дроти є. Потім:

```bash
stty -F /dev/ttyTHS3 115200 raw -echo -crtscts      # crtscts, якщо RTS-CTS теж з'єднано
cat /dev/ttyTHS3 &
echo hello > /dev/ttyTHS3                            # має повернутися "hello"
kill %1
```

Так перевіряється весь ланцюжок: Jetson → карта → дріт → карта → Jetson. Якщо плануєте швидкий обмін, повторіть на 921600 бод або вище, потім приберіть петлю й підключіть польотний контролер, як описано в [README](../../README.uk.md#польотний-контролер).

## 8. Якщо оверлей не застосовується

Вбудуйте оверлей у копію дерева пристроїв і завантажуйтеся з неї.

1. Знайдіть дерево пристроїв, яке використовується. Якщо в секції `LABEL` є рядок `FDT`, у ньому назва файлу. Інакше перегляньте `/boot/dtb/`: на платі розробника там зазвичай один файл `kernel_tegra234-p3768-0000+p3767-....dtb`.
2. Об'єднайте, підставивши цю назву замість `<your-kernel>`:

   ```bash
   sudo fdtoverlay -i /boot/dtb/<your-kernel>.dtb -o /boot/dtb/<your-kernel>-m2uart.dtb /boot/m2-keye-uartb.dtbo
   ```

3. У секції `LABEL` приберіть оверлей із рядка `OVERLAYS` і вкажіть рядок `FDT`, додавши його, якщо його немає:

   ```
         FDT /boot/dtb/<your-kernel>-m2uart.dtb
   ```

4. Перезавантажте й перевірте, як у кроці 5.

Після оновлення JetPack повторіть цей крок: оновлення встановлює нове дерево пристроїв, а об'єднана копія разом із ним не оновлюється.

## Пристрої з пропаленими запобіжниками й захищеним завантаженням

Пристрої з увімкненим захищеним завантаженням приймають лише підписані оверлеї й дерева пристроїв. На них оверлей треба вбудувати в підписане дерево пристроїв образу, який ви прошиваєте; кроки вище там не діють.

## JetPack 6.2.2

У цьому випуску є проблема з DMA у швидкому UART Orin: пошкоджені прийняті дані й помилки SMMU в `dmesg`. Виправлення NVIDIA для `serial@3100000` — запис `iommus = <&smmu_niso0 TEGRA234_SID_GPCDMA>;` у вузлі UART або робота UART без DMA. Для `serial@3110000`, що використовує той самий контролер DMA, його ніхто не підтвердив. Якщо в цьому випуску на RX приходить сміття, застосуйте те саме виправлення до цього вузла; як саме — пояснює коментар на початку файлу оверлею. Самому JetPack 6.2 це не потрібно: карту перевірено на ньому.

## Як скасувати

Поверніть початкові налаштування завантаження й перезавантажте:

```bash
sudo cp /boot/extlinux/extlinux.conf.orig /boot/extlinux/extlinux.conf
sudo reboot
```

Щоб знову користуватися Wi-Fi, вимкніть Jetson, вийміть карту й поставте на місце карту Wi-Fi з антенами.
